# Compound cut depths (tutorial stop #8)

A **compound** axis system combines two (or three) elementary orbits, and each orbit
carries its **own** cut depth — so the puzzle landscape is a 2-D square (or 3-D cube),
not the depth strip of the [elementary
systems](../tutorial_7_elementary_cut_depths). This folder holds the 2-orbit maps.

## The view

**`compound-gridsearch-heatmap.html`** — a self-contained HTML page (no server needed).
The 7 two-orbit systems as 2-D depth maps: one axis per orbit's depth (both shallow →
deep), each cell shaded by its **total piece count**, with thick walls separating cells
that belong to different **regimes**. Hover any cell for the two depths and the piece
breakdown. Reads `compound_data.js`.

## Why "gridsearch" (and why it's a lower bound)

Unlike the elementary systems — where a single shared depth makes the regime enumeration
*exact* — a compound system has a separate depth per orbit, so the ratio of depths
**reshapes** the plane arrangement itself. That adds a class of interior walls
(4-plane concurrencies, "quadruple" walls) that the elementary pair/triple method
misses, and which are expensive to enumerate exactly for the big dodeca systems. So the
data here is produced by **sampling a grid** (N=20 per axis) and grouping equal configs.

Consequence: the regime **count is a lower bound** — a regime thinner than a grid line
can be missed — and at N=20 the big systems are nearly all-distinct (e.g. Dodeca
corners+edges shows 385 regimes across 400 cells), so the grid barely resolves them.
Matching the surface lens used by the elementary heatmap is also future work (it needs
the flood-fill added to `precompute_compound.py`); these counts are by **total** pieces.

### Provenance
Generated by [`../lib/precompute_compound.py`](../lib/precompute_compound.py):
```bash
cd ../lib
python precompute_compound.py --n2=20 --dims=2   # -> tutorial_8_compound_cut_depths/compound_data.js
```
This is **slow** (the 20/30-ray dodeca systems take tens of minutes each). Per system:
`{rays, labels, N, depths, method:"grid", regimes:[{total,hist,maxw}], count, grid}` —
`grid` is an `N×N` array of regime ids. See the docstring in `precompute_compound.py`
for the exact-method write-up (the quadruple-wall problem).
