The 2-D depth square carved by the analytical {pair, triple, quadruple} walls (vertical decomposition — no dA gridsearch). Each tile is a chamber, bounded by the true wall curves and filled by its total piece count — smooth boundaries, deterministic counts. There are many more chambers than regimes (distinct puzzles); the count above each map is the regime count. Hover any chamber for its pieces.

Chambers vs. regimes — why there are more tiles than puzzles

Think of this square as a control panel: x is how deep you cut the first orbit, y how deep you cut the second. Every point is one specific puzzle. The walls are the curves where a specific geometric event happens — e.g. the crease between two cut-planes becomes tangent to the sphere. A chamber is one tile bounded by those walls: a patch you can slide around in without crossing any wall.

Here's the subtlety: a wall event is always geometrically real, but it only changes the actual puzzle if the feature it concerns is a live piece-boundary right there. If that crease grazes the sphere in a spot already sliced away by other cuts, nothing is created or destroyed — the wall fires in "dead space." So every puzzle change happens at a wall, but not every wall-crossing changes the puzzle, and two neighbouring chambers can be the exact same puzzle.

We enumerate every candidate wall (to guarantee no real change is missed), so the square gets cut into far more chambers than there are distinct puzzles — e.g. 352 chambers but only 52 regimes for the cube's faces+corners.
